# 常见的面试题答案

## 1. 如何判断用户设备

常见方案是组合判断，不建议只依赖单一字段：

- `navigator.userAgent`：通过 UA 判断 iOS、Android、PC、微信、钉钉等环境。
- `navigator.userAgentData`：Chromium 系浏览器提供的 Client Hints，隐私友好，但兼容性有限。
- 屏幕与输入能力：`window.innerWidth`、`matchMedia('(pointer: coarse)')`、`maxTouchPoints`。
- 服务端判断：根据请求头 `User-Agent` 做首屏分流。
- 响应式优先：多数情况下不要强依赖设备类型，而是通过 CSS 媒体查询和特性检测适配。

示例：

```js
const ua = navigator.userAgent.toLowerCase();
const isMobile = /iphone|ipad|ipod|android|mobile/.test(ua);
const isWeChat = /micromessenger/.test(ua);
const isTouch = navigator.maxTouchPoints > 0;
```

## 2. 将多次提交压缩成一次提交

常用 `git rebase -i`：

```bash
git rebase -i HEAD~3
```

把后面的提交从 `pick` 改成 `squash` 或 `fixup`，保存后重新编辑 commit message。若提交已经推到远端，需要：

```bash
git push --force-with-lease
```

`--force-with-lease` 比 `--force` 更安全，会避免覆盖别人新推送的提交。

## 3. 介绍下 navigator.sendBeacon 方法

`navigator.sendBeacon(url, data)` 用于在页面卸载、隐藏时可靠地异步发送少量数据，典型场景是埋点、日志上报。

特点：

- 不阻塞页面跳转或关闭。
- 浏览器会尽力在后台发送。
- 请求方法通常是 `POST`。
- 返回 `true` 只代表浏览器成功加入发送队列，不代表服务端成功接收。
- 数据量不宜过大，适合小体积日志。

```js
window.addEventListener('pagehide', () => {
  const data = JSON.stringify({ type: 'leave', time: Date.now() });
  navigator.sendBeacon('/api/track', new Blob([data], { type: 'application/json' }));
});
```

## 4. 混动跟随导航（电梯导航）该如何实现

核心是建立导航项和页面 section 的映射，滚动时计算当前 section，高亮对应导航；点击导航时滚动到对应区域。

实现方式：

- 使用 `IntersectionObserver` 观察每个楼层进入视口的比例。
- 或监听 `scroll`，结合 `getBoundingClientRect` 计算当前楼层。
- 点击导航时调用 `scrollIntoView({ behavior: 'smooth' })`。
- 加防抖或节流，避免滚动时频繁计算。
- 如果顶部有固定导航，需要处理 offset。

推荐 `IntersectionObserver`，性能更好。

```js
const observer = new IntersectionObserver(entries => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      setActive(entry.target.id);
    }
  });
}, { threshold: 0.5 });

document.querySelectorAll('section[id]').forEach(el => observer.observe(el));
```

## 5. 退出浏览器之前，发送积压的埋点数据请求，该如何做？

优先使用 `pagehide` + `navigator.sendBeacon`：

```js
function flushLogs() {
  if (!queue.length) return;
  const body = JSON.stringify(queue.splice(0));
  navigator.sendBeacon('/api/track/batch', new Blob([body], { type: 'application/json' }));
}

window.addEventListener('pagehide', flushLogs);
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'hidden') flushLogs();
});
```

补充：

- `beforeunload` 不可靠，还可能影响浏览器性能和 bfcache。
- `fetch` 可以配合 `keepalive: true`，但同样有数据大小限制。
- 埋点应支持批量、重试、去重，服务端也要能接受重复上报。

## 6. 如何统计页面的 long task（长任务）

浏览器主线程任务超过 50ms 会被认为是 Long Task。可以用 `PerformanceObserver` 监听 `longtask`。

```js
const observer = new PerformanceObserver(list => {
  for (const entry of list.getEntries()) {
    report({
      name: entry.name,
      startTime: entry.startTime,
      duration: entry.duration,
      attribution: entry.attribution
    });
  }
});

observer.observe({ entryTypes: ['longtask'] });
```

常见用途：

- 统计页面卡顿。
- 关联路由、设备、浏览器、资源加载状态。
- 结合用户行为定位卡顿发生在哪个流程。

注意兼容性，并做好采样，避免监控本身产生额外负担。

## 7. PerformanceObserver 如何测量页面性能

`PerformanceObserver` 可以异步订阅性能条目，常用于统计资源加载、导航耗时、LCP、CLS、FID/INP、Long Task 等。

```js
new PerformanceObserver(list => {
  for (const entry of list.getEntries()) {
    console.log(entry.name, entry.startTime, entry.duration);
  }
}).observe({ entryTypes: ['resource'] });
```

常见指标：

- `navigation`：DNS、TCP、TTFB、DOM 解析、load 总耗时。
- `resource`：JS、CSS、图片、接口等资源耗时。
- `paint`：FP、FCP。
- `largest-contentful-paint`：LCP。
- `layout-shift`：CLS。
- `longtask`：主线程长任务。

上报时一般要带页面 URL、路由、用户环境、采样率、网络类型。

## 8. 移动端如何实现下拉滚动加载（顶部加载）

顶部下拉加载常用于聊天记录分页。实现思路：

1. 监听滚动容器，判断 `scrollTop <= threshold`。
2. 触发加载上一页数据。
3. 记录加载前的 `scrollHeight`。
4. 数据插入顶部后，用新旧 `scrollHeight` 差值修正 `scrollTop`，避免视图跳动。

```js
const oldHeight = container.scrollHeight;
prependMessages(newMessages);
requestAnimationFrame(() => {
  container.scrollTop = container.scrollHeight - oldHeight;
});
```

注意处理加载锁、无更多数据、网络失败重试，以及 iOS 橡皮筋滚动兼容。

## 9. 判断页签是否为活跃状态

使用 Page Visibility API：

```js
document.addEventListener('visibilitychange', () => {
  if (document.visibilityState === 'visible') {
    resume();
  } else {
    pause();
  }
});
```

也可以使用：

- `document.hidden`
- `window.focus` / `window.blur`

实际项目中通常用 `visibilitychange` 控制轮询、视频播放、埋点停留时长、WebSocket 心跳策略。

## 10. 切片上传和整体上传耗时差不多的说法正确吗？

不完全正确。理论上带宽固定时，总传输字节数接近，总时间可能接近；但切片上传还有并发、重试、协议开销等因素。

切片上传优势：

- 可并发上传，提升链路利用率。
- 单片失败只重传失败片。
- 支持暂停、续传、秒传。
- 更容易显示进度。

劣势：

- 每个切片都有请求头、握手、调度开销。
- 服务端需要合并文件。
- 切片过小会导致请求数过多。

所以在弱网、大文件、需要断点续传时切片更有价值；小文件整体上传通常更简单。

## 11. 大文件切片上传确定切片数量有哪些考量

主要看切片大小，而不是直接决定切片数量。

考量因素：

- 文件大小：文件越大，切片大小可适当增大。
- 网络质量：弱网下切片不要太大，便于失败重试。
- 并发数：浏览器同域并发有限，通常控制在 3 到 6。
- 服务端限制：网关、对象存储、接口最大 body、超时时间。
- 内存占用：切片过大可能增加浏览器内存压力。
- 请求开销：切片过小会产生大量 HTTP 请求。
- 断点续传粒度：切片越小，续传浪费越少。

常见策略是 2MB、5MB、10MB 或动态切片。

## 12. 页面关闭时执行方法，该如何做

可以监听：

- `pagehide`：推荐，兼容 bfcache 场景更好。
- `visibilitychange`：页面隐藏时触发，适合提前处理。
- `beforeunload`：只适合弹确认，不适合可靠执行异步逻辑。
- `unload`：不推荐，可靠性差。

```js
window.addEventListener('pagehide', () => {
  navigator.sendBeacon('/api/leave', JSON.stringify({ time: Date.now() }));
});
```

页面关闭阶段不要依赖普通异步请求、定时器或复杂计算。

## 13. 如何统计用户 PV 访问的发起请求数量

可以在请求层做统一拦截统计：

- 封装 `fetch` / `XMLHttpRequest` / axios interceptor。
- 每次请求生成 requestId，记录 URL、方法、开始时间、状态、耗时。
- 按页面访问维度生成 pageId 或 sessionId。
- 页面隐藏或定时批量上报。

```js
let requestCount = 0;

axios.interceptors.request.use(config => {
  requestCount += 1;
  return config;
});

window.addEventListener('pagehide', () => {
  navigator.sendBeacon('/api/pv-request-count', JSON.stringify({
    page: location.href,
    count: requestCount
  }));
});
```

如果要统计静态资源，需要结合 Performance API 的 `resource` 条目。

## 15. 如何实现鼠标拖拽

核心是监听按下、移动、释放三类事件：

```js
el.addEventListener('mousedown', e => {
  const startX = e.clientX;
  const startY = e.clientY;
  const rect = el.getBoundingClientRect();

  function onMove(moveEvent) {
    el.style.transform = `translate(${rect.left + moveEvent.clientX - startX}px, ${rect.top + moveEvent.clientY - startY}px)`;
  }

  function onUp() {
    document.removeEventListener('mousemove', onMove);
    document.removeEventListener('mouseup', onUp);
  }

  document.addEventListener('mousemove', onMove);
  document.addEventListener('mouseup', onUp);
});
```

实际项目要考虑边界限制、吸附、节流、移动端 pointer 事件、拖拽期间禁用选中文本等。

## 16. 统计全站每一个静态资源加载耗时

使用 `PerformanceObserver` 监听 `resource`：

```js
new PerformanceObserver(list => {
  for (const entry of list.getEntries()) {
    report({
      name: entry.name,
      initiatorType: entry.initiatorType,
      duration: entry.duration,
      transferSize: entry.transferSize,
      startTime: entry.startTime
    });
  }
}).observe({ type: 'resource', buffered: true });
```

注意：

- 跨域资源如果没有 `Timing-Allow-Origin`，部分详细时间不可见。
- 上报要采样，避免数据量过大。
- 可以按 JS、CSS、图片、字体、接口分类统计。

## 17. 防止前端页面重复请求

常见手段：

- 按钮点击后禁用或进入 loading。
- 请求去重：相同 key 的请求复用同一个 Promise。
- 请求取消：新请求发出时取消旧请求。
- 防抖/节流：搜索、滚动、resize 等高频场景。
- 缓存：短时间内相同参数直接读缓存。
- 服务端幂等：提交类接口使用幂等 key。

```js
const pending = new Map();

function requestOnce(key, requestFn) {
  if (pending.has(key)) return pending.get(key);
  const p = requestFn().finally(() => pending.delete(key));
  pending.set(key, p);
  return p;
}
```

## 18. ResizeObserver 作用是什么

`ResizeObserver` 用来监听元素尺寸变化，而不是窗口尺寸变化。

适用场景：

- 图表容器变化后重绘。
- 文本容器变化后重新计算省略。
- 响应式组件根据自身宽度调整布局。
- 虚拟列表容器尺寸变化后重新计算可视区域。

```js
const observer = new ResizeObserver(entries => {
  for (const entry of entries) {
    console.log(entry.contentRect.width, entry.contentRect.height);
  }
});

observer.observe(document.querySelector('.panel'));
```

组件卸载时要 `disconnect`，避免泄漏。

## 19. 要实时统计用户浏览器窗口大小，该如何做

监听 `resize`，并做节流：

```js
function reportSize() {
  report({
    width: window.innerWidth,
    height: window.innerHeight,
    dpr: window.devicePixelRatio
  });
}

window.addEventListener('resize', throttle(reportSize, 300));
```

如果关心某个容器大小，应使用 `ResizeObserver`。如果是移动端，还要考虑横竖屏变化、软键盘弹起、`visualViewport`。

## 20. 定位是哪个 commit 引入错误，该怎么做

使用 `git bisect` 二分定位：

```bash
git bisect start
git bisect bad
git bisect good <正常的commit>
```

Git 会切到中间提交，运行测试或手动验证：

```bash
git bisect good
# 或
git bisect bad
```

直到定位到第一个坏提交。结束后：

```bash
git bisect reset
```

如果有自动化测试，可以用：

```bash
git bisect run npm test
```

## 21. 如何移除一个指定的 commit

分两种情况：

- 已推送公共分支：用 `git revert <commit>` 生成反向提交，更安全。
- 未推送或个人分支：可用 `git rebase -i` 删除该 commit。

```bash
git revert <commit-sha>
```

如果移除的是 merge commit，需要指定父提交：

```bash
git revert -m 1 <merge-commit-sha>
```

## 22. 如何还原用户操作流程

前端监控里常用用户行为链路记录：

- 路由跳转：记录页面访问顺序。
- 点击、输入、滚动、接口请求、错误日志。
- 给每次会话生成 sessionId，每次页面访问生成 pageId。
- 记录关键 DOM 信息，如按钮文案、元素路径、业务 ID。
- 用时间线串起来，还原“用户先做了什么，后发生了什么”。
- 可接入 rrweb 一类方案录制 DOM 快照和增量变化。

注意隐私合规，敏感输入要脱敏或不采集。

## 23. 可否将请求调用源码地址和代码行数上报？

可以，但需要权衡准确性和成本。

方案：

- 开发环境可通过 `Error().stack` 获取调用栈。
- 生产环境由于代码压缩，需要 sourcemap 还原。
- 在请求封装层创建 Error，解析 stack，得到调用文件、行列号。
- 上报 sourcemap 后由监控平台反解源码位置。

```js
function request(config) {
  const stack = new Error().stack;
  return realRequest(config).catch(error => {
    report({ error, stack });
    throw error;
  });
}
```

注意：生产上报 stack 可能有性能和隐私风险，应采样或仅错误时上报。

## 24. 批量请求失败只弹出一个 toast

可以做错误提示聚合：

- 统一请求拦截器处理错误。
- 短时间窗口内只展示一次相同错误。
- 对批量请求使用业务层统一 catch。
- 给请求配置 `silent`，由页面统一提示。

```js
let toastTimer = null;

function showErrorOnce(message) {
  if (toastTimer) return;
  toast(message);
  toastTimer = setTimeout(() => {
    toastTimer = null;
  }, 1000);
}
```

更完整的做法是按错误码、接口场景、页面维度做合并，避免关键错误被吞掉。

## 25. 如何减少项目里面 if-else

常见方式：

- 提前返回，减少嵌套。
- 使用策略模式或映射表。
- 用多态替代类型判断。
- 把复杂条件抽成语义化函数。
- 用配置驱动业务差异。
- 对状态流转使用状态机。

```js
const handlers = {
  pending: handlePending,
  success: handleSuccess,
  failed: handleFailed
};

handlers[status]?.();
```

但不要为了消灭 `if` 而过度抽象，简单条件直接写 `if` 更清晰。

## 26. babel-runtime 作用是什么

`babel-runtime` 主要用于复用 Babel 编译产生的 helper 函数，并避免污染全局环境。

作用：

- 避免每个文件重复注入 `_extends`、`_classCallCheck` 等 helper。
- 配合 `@babel/plugin-transform-runtime` 引入公共 helper。
- 使用 `core-js` 模块化 polyfill，避免直接修改全局对象。
- 适合类库开发，减少全局污染风险。

应用项目通常可以直接用 `@babel/preset-env` + polyfill；类库更适合 transform-runtime。

- 使用 PDF.js：兼容性和自定义能力更强。

## 28. 如何在划词选择的文本上添加右键菜单

监听 `mouseup` 或 `selectionchange` 获取选区，再监听 `contextmenu` 展示自定义菜单。

```js
document.addEventListener('contextmenu', e => {
  const selection = window.getSelection();
  const text = selection?.toString().trim();
  if (!text) return;

  e.preventDefault();
  showMenu({ x: e.clientX, y: e.clientY, text });
});
```

关键点：

- 用 `window.getSelection()` 获取选中文本。
- 用 `Range.getBoundingClientRect()` 获取选区位置。
- 点击外部关闭菜单。
- 富文本场景要保留选区，避免菜单点击时 selection 丢失。

## 29. 富文本里面是如何做到划词的？

富文本划词依赖 Selection 和 Range API。

- `window.getSelection()` 获取当前选区。
- `selection.getRangeAt(0)` 获取范围。
- Range 包含起点节点、终点节点、偏移量。
- 可以通过 `range.surroundContents` 包裹选区，但复杂 DOM 下容易失败。
- 更稳妥的方式是把选区映射到富文本编辑器自己的文档模型。

成熟编辑器如 ProseMirror、Slate、Quill 都会维护内部文档模型，划词后把 DOM selection 转成 model selection，再执行加粗、评论、标注等操作。

## 30. 如何做好前端监控方案

前端监控通常包括四类：

- 稳定性：JS 错误、Promise 错误、资源加载错误、接口错误。
- 性能：FCP、LCP、CLS、INP、TTFB、资源耗时、长任务。
- 用户行为：PV、UV、点击、路由、停留时长、操作链路。
- 业务指标：下单成功率、支付失败率、核心流程转化。

技术设计：

- SDK 采集，统一封装上报。
- 数据批量发送，使用采样、节流、去重。
- 页面隐藏时用 `sendBeacon` 兜底。
- 每条数据携带 app、version、route、userId、sessionId、traceId。
- 错误接入 sourcemap 还原源码。
- 后台做聚合、告警、看板、问题分派。

重点是从“能收集”走到“能定位、能告警、能闭环”。

## 31. 如何标准化处理线上用户反馈的问题

标准流程：

1. 收集用户信息：账号、设备、浏览器、时间、入口、操作步骤。
2. 查询监控：错误日志、接口日志、性能指标、用户行为链路。
3. 复现问题：同环境、同版本、同数据。
4. 定位原因：前端、后端、网络、数据、权限、兼容性。
5. 制定方案：临时止血和长期修复分开。
6. 验证上线：补充测试、灰度发布、观察指标。
7. 复盘沉淀：补监控、补文档、补自动化用例。

核心是让反馈从“截图和口述”变成“可查询、可复现、可追踪”的问题单。

## 32. px 如何转为 rem

`rem` 相对于根元素 `html` 的 `font-size`。例如：

```css
html {
  font-size: 16px;
}

.title {
  font-size: 1rem; /* 16px */
}
```

移动端常见方案：

- 设计稿宽度 750px。
- 设置 `html.fontSize = viewportWidth / 10`。
- 75px 转成 1rem。

工程里通常用 PostCSS 插件自动转换，如 `postcss-pxtorem`。也可以使用 `vw` 方案，减少 JS 动态设置根字体的依赖。

## 33. 为何 CDN 请求资源没有跨域限制

同源策略主要限制脚本读取跨域响应内容，不是禁止所有跨域请求。

`<script>`、`<img>`、`<link>` 等标签天然允许跨域加载资源，例如：

```html
<script src="https://cdn.example.com/lib.js"></script>
<img src="https://cdn.example.com/a.png">
```

但限制仍然存在：

- JS 可以加载跨域脚本，但无法直接读取脚本响应文本。
- Canvas 使用跨域图片后，如果没有正确 CORS，会被污染，不能读取像素。
- 字体、模块脚本、fetch 请求通常需要 CORS。

所以 CDN 静态资源能加载，不代表浏览器完全没有跨域限制。

## 34. cookie 可以实现不同域共享吗

严格意义上，不同主域不能共享 Cookie。例如 `a.com` 和 `b.com` 不能直接共享。

同一主域下的子域可以通过 `Domain` 共享：

```http
Set-Cookie: token=xxx; Domain=.example.com; Path=/
```

这样 `a.example.com` 和 `b.example.com` 都能携带该 Cookie。

跨主域登录通常用：

- 单点登录 SSO。
- OAuth/OIDC。
- 中心登录页跳转传 token。
- 后端换取各业务域自己的登录态。

还要注意 `SameSite`、`Secure`、第三方 Cookie 限制。

## 35. axios 是否可以取消请求

可以。新版 axios 推荐使用 `AbortController`：

```js
const controller = new AbortController();

axios.get('/api/list', {
  signal: controller.signal
});

controller.abort();
```

旧版本使用 `CancelToken`，但已经不推荐。

常见场景：

- 搜索输入时取消上一次请求。
- 路由切换时取消当前页面请求。
- 组件卸载时取消未完成请求。

## 36. 前端如何实现折叠面板效果？

基本思路是维护展开状态，控制内容区域高度。

```css
.panel-body {
  overflow: hidden;
  transition: height 0.2s ease;
}
```

实现方式：

- 简单场景：用 `display: none/block`，但没有高度动画。
- 动画场景：从 `0` 到 `scrollHeight` 过渡。
- 现代 CSS：用 grid 的 `grid-template-rows: 0fr -> 1fr`。
- 无障碍：按钮设置 `aria-expanded`，内容区关联 `aria-controls`。

面试可以补充：多面板互斥展开就是手风琴模式。

## 37. DOM 中如何判定 a 元素是否是 b 元素的子元素

使用 `contains`：

```js
const isChild = b.contains(a) && a !== b;
```

如果允许自身也算子元素，可以去掉 `a !== b`。

也可以用 `compareDocumentPosition`：

```js
Boolean(b.compareDocumentPosition(a) & Node.DOCUMENT_POSITION_CONTAINED_BY);
```

## 38. 判断一个对象是否为空，包含原型链上的自定义数据或方法

如果“空”要求包括原型链也没有自定义属性，可以用 `for...in`，它会遍历对象自身和原型链上的可枚举属性。

```js
function isEmptyWithProto(obj) {
  if (obj == null || typeof obj !== 'object') return false;

  for (const key in obj) {
    return false;
  }

  return true;
}
```

如果原型链上的方法是不可枚举的，`for...in` 检测不到，需要沿原型链配合 `Object.getOwnPropertyNames` 判断，但通常还要排除 `Object.prototype` 上的内建属性。

## 39. is 如何判空

题目定义中：空数组、空对象、空字符串、`0`、`undefined`、`null`、空 `Map`、空 `Set` 都算空。

```js
function isEmpty(value) {
  if (value == null) return true;
  if (value === 0) return true;
  if (typeof value === 'string') return value.trim().length === 0;
  if (Array.isArray(value)) return value.length === 0;
  if (value instanceof Map || value instanceof Set) return value.size === 0;
  if (typeof value === 'object') return Object.keys(value).length === 0;
  return false;
}
```

注意：`false` 是否算空要看业务定义；`NaN` 是否算空也需要提前约定。

## 40. CSS 实现翻牌效果

核心是 3D 变换：

```css
.card {
  perspective: 1000px;
}

.inner {
  position: relative;
  transform-style: preserve-3d;
  transition: transform 0.6s;
}

.card:hover .inner {
  transform: rotateY(180deg);
}

.front,
.back {
  position: absolute;
  inset: 0;
  backface-visibility: hidden;
}

.back {
  transform: rotateY(180deg);
}
```

父元素设置透视，内部元素旋转，正反两面用 `backface-visibility: hidden` 隐藏背面。

## 41. flex: 1 代表什么

`flex: 1` 是简写，通常等价于：

```css
flex: 1 1 0%;
```

含义：

- `flex-grow: 1`：有剩余空间时放大。
- `flex-shrink: 1`：空间不足时缩小。
- `flex-basis: 0%`：分配空间前基础尺寸按 0 计算。

所以多个子项都设置 `flex: 1` 时，会平均分配剩余空间。

## 42. 一般是怎么做代码重构的

重构要小步、可验证、可回滚。

流程：

1. 明确目标：降低复杂度、消除重复、提升性能、拆分模块等。
2. 补测试或确认现有用例覆盖关键行为。
3. 梳理依赖和边界，避免扩大影响面。
4. 小步提交，每一步保持可运行。
5. 用类型检查、单测、集成测试、灰度验证结果。
6. 保持对外 API 和行为兼容，必要时做迁移层。

重构不是重写，重点是改善内部结构，同时保持外部行为稳定。

可结合工具和人工确认：

- JS/TS：`ts-prune`、`knip`、`depcheck`、ESLint no-unused 规则。
- CSS：Chrome Coverage、PurgeCSS、Tailwind content 扫描。
- 依赖：`depcheck`、包管理器分析。
- 构建产物：webpack-bundle-analyzer、rollup visualizer。

步骤上建议先统计、再分批删除、跑测试和构建，最后观察线上错误。

## 44. 前端应用如何做国际化

核心是把文案、日期、数字、货币、方向、资源都从业务代码中抽离。

常见方案：

- 使用 i18next、vue-i18n、react-intl 等库。
- 文案用 key 管理：`t('user.profile.title')`。

## 45. 应用如何做灰度发布

灰度发布是让一部分用户先使用新版本，观察稳定后逐步放量。

常见维度：

- 用户 ID 白名单。
- 百分比流量。
- 地区、租户、渠道、设备类型。
- AB 实验分组。

前端实现：

- 构建时多版本产物。
- 网关或 CDN 按规则分发不同资源。
- 配置中心下发开关。
- 前端根据 feature flag 展示新功能。

## 46. 微前端为何通常不选择 iframe 方案

iframe 隔离性强，但体验和工程成本较高：

- 路由同步复杂。
- 父子通信麻烦。
- 弹窗、遮罩、定位、拖拽体验受限。
- SEO 和首屏性能较差。
- 登录态、权限、埋点、主题共享成本高。
- UI 无法自然融合，样式和布局边界明显。

但 iframe 不是完全不能用。对强隔离、第三方系统、安全边界要求很高的场景，它反而是合适选择。

## 47. Qiankun 是如何做 JS 隔离的

Qiankun 主要通过沙箱隔离子应用运行时对全局对象的影响。

常见机制：

- `ProxySandbox`：用 `Proxy` 代理 `window`，子应用读写优先发生在代理对象上。
- `SnapshotSandbox`：不支持 Proxy 时，进入前记录全局状态，退出时恢复。
- 生命周期隔离：子应用 mount/unmount 时激活和失活沙箱。
- 动态脚本执行时把上下文绑定到沙箱 window。

JS 隔离主要解决全局变量污染问题，但定时器、事件监听、DOM 副作用仍需要子应用自己在卸载时清理。

## 48. 微前端架构一般如何做 JavaScript 隔离

常见方案：

- iframe：浏览器原生强隔离。
- Proxy 沙箱：代理 `window`，记录和隔离全局读写。
- 快照沙箱：进入应用前后记录全局差异并恢复。
- 构建隔离：模块作用域、UMD/SystemJS、避免暴露全局变量。
- 运行时约束：统一生命周期，卸载时清理事件、定时器、全局状态。
- ShadowRealm 等新能力：目前实际落地有限。

实际项目一般还要配合 CSS 隔离、资源加载隔离、状态通信规范。

## 49. React 循环渲染为什么不推荐用 index 做 key

React 用 `key` 判断列表项身份。使用 index 时，如果列表发生插入、删除、排序，元素身份会错乱。

可能问题：

- 组件状态复用到错误的数据上。
- 输入框内容错位。
- 动画和焦点异常。
- 不必要的重新渲染。

只有列表完全静态、不排序、不插入删除时，用 index 才相对安全。更推荐使用业务唯一 ID。

## 50. React 如何避免 context 引起整个挂载节点树重新渲染

Context 的 value 变化会通知所有消费该 context 的组件。优化方式：

- 拆分 context：状态、dispatch、不同业务域分开。
- `useMemo` 固定 value 引用。
- 把频繁变化的数据下沉到局部状态或外部 store。
- 使用 selector 方案，如 `use-context-selector`。
- 消费组件配合 `React.memo`，减少子树继续渲染。

```jsx
const value = useMemo(() => ({ user, updateUser }), [user]);
```

原则是不要把一个巨大且频繁变化的对象塞进单个 context。

## 51. 前端如何实现截图？

常见方案：

- DOM 截图：`html2canvas`，把 DOM 渲染到 canvas。
- SVG foreignObject：适合部分结构，兼容性要验证。
- Canvas 本身：直接导出 `canvas.toDataURL()`。
- 视频截图：把 video 当前帧绘制到 canvas。
- 服务端截图：Puppeteer/Playwright 渲染页面后截图。

- 大页面截图容易内存过高。

## 52. 当 QPS 达到峰值时，该如何处理？

前端侧可以做削峰和降级：

- 防抖、节流、请求合并。
- 缓存热点数据，减少重复请求。
- 限制并发，排队执行。
- 非核心请求延后或丢弃。
- 页面降级，减少自动刷新和轮询。
- 静态资源走 CDN，接口走缓存。

系统侧需要：

- 网关限流、熔断、降级。
- 服务扩容。
- 消息队列削峰。
- 数据库读写分离和缓存。

面试回答要强调：前端能缓解，但最终需要全链路治理。

## 53. JS 超过 Number 最大值的数怎么处理？

`Number.MAX_SAFE_INTEGER` 是 `9007199254740991`，超过后整数精度不可靠。

处理方式：

- 使用 `BigInt`：

```js
const id = 9007199254740993n;
```

- 后端把大整数 ID 作为字符串返回。
- 前端展示和传输时保持字符串，不做 Number 运算。
- 需要高精度小数时使用 decimal.js、big.js 等库。

注意 `BigInt` 不能和普通 Number 直接混算，也不能直接 JSON 序列化。

## 56. 如何解决页面请求接口大规模并发问题

前端可从控制并发和减少请求两方面处理：

- 请求合并：多个相似请求合成一个批量接口。
- 请求缓存：相同参数复用结果。
- 并发池：限制同时进行的请求数量。
- 优先级：核心请求优先，低优先级延后。
- 取消无效请求：路由切换、搜索输入变化时 abort。
- 分页和懒加载：不要一次请求所有数据。
- 错误重试退避：避免失败后立即雪崩重试。

并发池示例：

```js
async function runWithLimit(tasks, limit) {
  const results = [];
  const executing = new Set();

  for (const task of tasks) {
    const p = Promise.resolve().then(task);
    results.push(p);
    executing.add(p);
    p.finally(() => executing.delete(p));
    if (executing.size >= limit) await Promise.race(executing);
  }

  return Promise.all(results);
}
```

## 57. 设计一套全站请求耗时统计工具

设计要点：

- 统一拦截请求：封装 fetch、XHR、axios。
- 生成 requestId，记录开始时间和结束时间。
- 采集 URL、method、status、duration、业务 code、traceId。
- 对 URL 做归一化，避免 `/user/1` 和 `/user/2` 被拆成太多指标。
- 支持采样、批量上报、失败重试。
- 页面隐藏时用 `sendBeacon` 刷新队列。
- 与后端 traceId 打通，定位链路慢点。

```js
const start = performance.now();
try {
  const res = await fetch(url, options);
  report({ url, status: res.status, duration: performance.now() - start });
  return res;
} catch (error) {
  report({ url, status: 0, duration: performance.now() - start, error: String(error) });
  throw error;
}
```

后台侧要提供接口维度、页面维度、版本维度、地区维度的统计看板。

## 58. 大文件上传了解多少

大文件上传常见能力：

- 文件切片：用 `file.slice` 拆分。
- 并发上传：控制 3 到 6 个并发。
- 断点续传：服务端记录已上传分片。

流程：

3. 查询已上传分片。
4. 上传缺失分片。
5. 通知服务端合并。
6. 校验文件完整性。

## 59. H5 如何解决移动端适配问题

## 61. 如何实现网页加载进度条？

常见方案：

- 路由切换进度条：如 NProgress。
- 请求进度：axios/fetch 结合进度事件。
- 资源加载进度：统计关键资源加载完成数量。

## 62. 常见图片懒加载方式有哪些？

## 63. Cookie 构成部分有哪些

Cookie 常见字段：

- `Name=Value`：键值对。
- `Domain`：可访问该 Cookie 的域。
- `Path`：可访问路径。
- `Expires` / `Max-Age`：过期时间。
- `HttpOnly`：禁止 JS 读取，降低 XSS 窃取风险。
- `Secure`：仅 HTTPS 发送。
- `SameSite`：控制跨站请求是否携带，常见 `Lax`、`Strict`、`None`。

示例：

```http
Set-Cookie: token=abc; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=3600
```

## 64. 扫码登录实现方式

典型流程：

1. Web 端向服务端申请二维码 ID。
2. 服务端生成二维码，二维码中包含临时 token 或 loginId。
3. Web 端轮询二维码状态，或使用 WebSocket/SSE 等待状态变化。
4. App 扫码后识别 loginId，展示确认登录页。
5. 用户确认后，App 通知服务端授权。
6. Web 端收到授权状态后换取登录态。

安全点：

- 二维码短期有效。
- 扫码后必须二次确认。
- loginId 只能使用一次。
- Web 端和 App 端状态绑定，防止冒用。
- 全程 HTTPS。

## 65. DNS 协议了解多少

DNS 用于把域名解析为 IP 地址。

解析流程：

- 浏览器缓存。
- 操作系统缓存。
- 本地 DNS 服务器。
- 根域名服务器。
- 顶级域名服务器，如 `.com`。
- 权威 DNS 服务器。

常见记录：

- `A`：IPv4 地址。
- `AAAA`：IPv6 地址。
- `CNAME`：别名。
- `MX`：邮件服务器。
- `TXT`：文本验证。
- `NS`：域名服务器。

优化方式：

- DNS 缓存。
- DNS 预解析：`<link rel="dns-prefetch" href="//cdn.example.com">`。
- 减少域名数量。
- 使用稳定的 CDN 和智能解析。

## 66. 函数式编程了解多少？

函数式编程强调用函数组合处理数据，减少可变状态和副作用。

核心概念：

- 纯函数：相同输入总是相同输出，不修改外部状态。
- 不可变数据：避免直接修改原对象。
- 高阶函数：函数作为参数或返回值。
- 函数组合：把多个小函数组合成复杂逻辑。
- 声明式：关注“做什么”，少写“怎么一步步做”。

示例：

```js
const total = list
  .filter(item => item.checked)
  .map(item => item.price)
  .reduce((sum, price) => sum + price, 0);
```

优点是可测试、可复用、逻辑清晰；缺点是过度抽象时可读性下降。

## 67. 前端水印了解多少？

前端水印常用于防截图传播和责任追踪。

实现方式：

- DOM 水印：创建覆盖层，重复渲染用户名、时间等。
- Canvas 生成背景图：把文字绘制到 canvas，再作为背景平铺。
- SVG 背景水印。
- 服务端水印：对图片、PDF、视频直接加水印，防篡改更强。

前端水印防删除手段：

- 使用 `MutationObserver` 监听水印节点被删除后重建。
- 设置高 `z-index`、`pointer-events: none`。
- 多位置重复渲染。

但前端水印无法绝对防篡改，只能提高成本；敏感文件更应使用服务端水印和权限控制。

## 68. 什么是领域模型

领域模型是对业务领域中核心概念、规则和关系的抽象表达。

例如电商领域中可能有：

- 用户
- 商品
- 订单
- 支付
- 库存
- 优惠券

领域模型不只是数据库表，也不只是前端类型定义，而是业务语义本身。它回答：

- 业务中有哪些核心对象？
- 它们之间是什么关系？
- 规则和状态流转是什么？
- 哪些行为属于这个对象？

好的领域模型可以让代码更贴近业务语言，降低沟通成本，也让复杂业务更容易维护。
